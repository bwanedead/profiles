# Profiles Repository

A shareable source for cross-machine shell profile configurations.

## Purpose

This repository serves as the **single source of truth** for shell profiles and related configuration files. Instead of maintaining separate profile configurations on each machine, all machines point to this centralized repo.

## Supported Configurations

| File | Description |
|------|-------------|
| `Microsoft.PowerShell_profile.ps1` | PowerShell 7 profile |
| `ryan.omp.json` | Oh My Posh terminal theme |

## Setup Instructions

### Initial Setup (New Machine)

1. **Clone this repository:**
   ```powershell
   git clone https://github.com/bwanedead/profiles.git C:\projects\profiles
   ```

2. **Create the pointer file:**

   Open your system profile:
   ```powershell
   notepad $PROFILE
   ```

   Replace the entire contents with this pointer file:
   ```powershell
   # ============================================================================
   # DO NOT EDIT THIS FILE
   # ============================================================================
   #
   # This is a pointer file. All profile logic lives in the git repository:
   #
   #   Repository: https://github.com/bwanedead/profiles
   #   Local path: C:\projects\profiles\Microsoft.PowerShell_profile.ps1
   #
   # To make changes:
   #   1. Run: prof edit        (opens the repo version in notepad)
   #   2. Or:  notepad "C:\projects\profiles\Microsoft.PowerShell_profile.ps1"
   #   3. After editing, reload with: . $PROFILE
   #   4. Commit and push to sync across machines
   #
   # Why this setup?
   #   - Single source of truth for profile logic
   #   - Version controlled with full git history
   #   - Cross-machine sync via git push/pull
   #   - See AGENTS.md in the repo for full documentation
   #
   # ============================================================================

   . "C:\projects\profiles\Microsoft.PowerShell_profile.ps1"
   ```

3. **Reload your profile:**
   ```powershell
   . $PROFILE
   ```

### Why the Pointer File Matters

The system profile (`$PROFILE`) should **only** contain the pointer—never actual logic. This ensures:

- **AI agents** that open `$PROFILE` see clear instructions to edit the repo instead
- **Users** are reminded where the real config lives
- **Accidents** are prevented—editing the wrong file won't happen
- **Clean separation** between the OS-required file location and the versioned source

### Daily Workflow

**Editing the profile:**
```powershell
prof edit          # Opens repo version in notepad
# Make changes, save
. $PROFILE         # Reload to apply changes
```

**Syncing changes:**
```powershell
prof               # Navigate to repo
git add -A && git commit -m "Update profile"
git push
```

**Pulling updates on another machine:**
```powershell
prof               # Navigate to repo
git pull
. $PROFILE         # Reload to apply changes
```

## Benefits

- **Single source of truth** - One place to maintain all profile logic
- **Version controlled** - Full history of changes, easy rollback
- **Cross-machine sync** - Push/pull to keep machines in sync
- **Shareable** - Others can fork and adapt for their own use
- **Backup** - Profile is safely stored in git, not just locally

## Adding New Profile Types

To add support for other shells (bash, zsh, etc.):

1. Add the config file to this repo
2. Update this README with setup instructions
3. On each machine, configure the shell to source from the repo
